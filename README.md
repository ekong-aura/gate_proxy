## 一、这个项目是用来干什么的？

在海外 VPS 上一键搭建 **全球真实家庭宽带（住宅 IP）出口代理**。把 VPS 的流量中继到全球家宽的志愿者节点，用于流媒体、区域限制内容、账号环境一致性等场景，自带可视化管理面板与多隧道自愈守护。

> **v3 · 多隧道聚合版**：N 条独立隧道并行 + gost 按连接轮询分流，等效带宽叠加；逐隧道独立自愈，单条掉线不影响业务；节点评分按实测分布标定，优先抢冷门节点。
> 架构演进与缺陷审计见 [`FIXES.md`](FIXES.md)。

## 二、为什么这样设计（性能关键）

VPN Gate 节点的瓶颈**不是 IP 质量**（它们本身就是真实 ISP 住宅段，反欺诈分通常很低），而是**并发人数**。实测当前节点池：

| 指标 | p25 | 中位 | p75 | 最大 |
|---|---|---|---|---|
| `NumVpnSessions`（当前并发） | 4 | 25 | 63 | 184 |
| `Speed`（历史测速） | 89M | 195M | 441M | 973M |
| `Ping` | 9ms | 26ms | 33ms | 170ms |
| `TotalUsers`（累计用户） | 7.8k | 54k | 240k | 14.4M |

一个节点被 25 个人分，和你独享完全是两回事。所以 v3 做了两件事：

1. **评分重写**：并发人数占一半权重，把「ping 最低但挤着 70 人」的节点排到最后
2. **多隧道聚合**：3 条隧道 × 各自独享一个冷门节点 = 并发压力除以 3

实测对比（同一份节点池，取日本前 10 名）：

| 策略 | 平均并发人数 | 平均标称带宽 |
|---|---|---|
| 按 Ping 排序（v1/v2） | **38.2 人** | 468 Mbps |
| 智能评分（v3） | **5.9 人** | 427 Mbps |
| 效果 | **并发压力 ↓85%** | 基本持平 |

并发压力降 85%，意味着你抢到的实际带宽是原来的数倍。

├── vpngate_credentials.json  面板登录账号密码（600）

只保留三个例外（都必须在标准位置，不能挪）：

| 路径 | 为什么不能挪 |
|---|---|
| `/usr/local/bin/gost`、`/usr/local/bin/vg` | 要在 `$PATH` 里才能直接敲命令 |
| `/etc/systemd/system/vpngate*.service` | systemd 只认这个目录 |
| `/etc/sysctl.d/99-vpngate.conf` | 内核参数开机加载位置 |

想换目录的话（比如 `/data/gate_proxy`），安装时带上环境变量即可：

```bash
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/install.sh | INSTALL_DIR=/data/gate_proxy bash
```

从旧版本升级时，会**自动把 `/opt` 下的缓存和节点池迁移过来**，池子不会丢。


### 接入协议（每个入口都共用同一组 tun，所以都自动获得多隧道无感切换）

| 端口 | 协议 | 用途 |
|---|---|---|
| `10808` | **SOCKS5 + HTTP**（同一端口自动识别） | 聚合入口。出口在 N 条隧道间轮询 —— **每次请求都可能换 IP** |
| `10818` `10819` `10820` … | **SOCKS5 + HTTP**（每条隧道一个） | **粘性出口**。固定只走一条隧道，出口 IP 不跳动 |
| `10809` | Shadowsocks AEAD `aes-256-gcm` | 老客户端兼容 |
| `10810` | Shadowsocks 2022 `blake3-aes-256-gcm` | 防重放，需客户端支持 SS2022 |
| `10811` | Shadowsocks UDP 中继（UDP 端口） | Telegram 语音 / 游戏 / QUIC 网站 |
| `5000` | Web 面板 | 管理 |

> gost 3.3.3 实测结论：`auto`（SOCKS5+HTTP 同端口 + 认证）、`ssu`、`ss 2022-blake3-aes-256-gcm` 都可用；
> `2022-blake3-chacha20-poly1305` 报 `cipher not supported`，所以 SS2022 只用 aes 系列。

### 聚合口 vs 粘性口

```
客户端 ──10808（聚合）──> gost ──轮询──> tun0 / tun1 / tun2   ← IP 每条连接都可能不同
客户端 ──10818（粘性）──> gost ───────> tun0                  ← 只要 tun0 不断，IP 就一直是同一个
```

**聚合口**：多条隧道的带宽叠加，吞吐更好，但同一个网站的两次请求可能来自两个不同的住宅 IP。

**粘性口**：固定绑一条隧道，只要那条隧道连着，出口 IP 就一直是同一个。
适合任何"希望出口地址稳定"的场景 —— 不管你是做账号环境、API 白名单，还是只想让某个服务看到固定的来源 IP。

### 什么是「隧道」，为什么有多条

**一条隧道 = 一条独立 OpenVPN 连接 = 一个家宽出口。** 每条隧道连到一台不同的志愿者电脑，
各有各的出口 IP、带宽和延迟 —— `tun0` 和 `tun1` 不是主备关系，而是两个**平行**的出口。

为什么要多条：

| 目的 | 说明 |
|---|---|
| **带宽叠加** | 单条隧道速度受限于那台家宽电脑（常见 5~30Mbps）。多条并行，分段请求可以分摊，总吞吐接近翻倍 |
| **抗单点故障** | 志愿者电脑随时关机。两条掉一条，另一条继续服务，只损失一半而非全断 |
| **秒级切换** | 一条挂掉时另一条**已经连好在线**，不用临时找节点等握手 |

**连接时走哪一条，由你用的端口决定：**

| 端口 | 走哪条隧道 |
|---|---|
| 聚合口 `10808` | **不确定** —— gost 按新建连接逐条轮询（第 1 个连接 tun0、第 2 个 tun1、第 3 个又回 tun0），一条连不上自动落到下一条 |
| 粘性口 `10818` | **一定**是 tun0 |
| 粘性口 `10819` | **一定**是 tun1 |

所以"用哪条隧道连接"不需要按钮切换 —— **想固定走某条，就复制那张隧道卡片上的「专属入口」**。
1 核机器安装时会自动把隧道数从 3 降到 2（OpenVPN 单线程），4 核以上可用 `TUNNELS=4`。

### 刷新频率

| 层 | 频率 |
|---|---|
| 面板页面拉数据 | 每 **8 秒** |
| 后端巡检（正常时） | 每 **30 秒** 一轮，数值可在参数设置里改 |
| 后端巡检（有隧道故障时） | 每 **5 秒** 一轮 |
| 掉线检测：设备消失 | **1 秒**级轮询 |
| 掉线检测：出网探测 | **3 秒**级，连续 2 次失败才判死 |
| OpenVPN 自身断链判定 | `ping 3` + `ping-restart 20` |

#### ⚠️ 粘性口不保证 IP 永远不变

这一点必须说清楚：

- **节点是志愿者家里的电脑，随时可能关机、断网、被拔电源。**
- 一旦那条隧道掉线，守护进程必须换一个节点才能恢复，**出口 IP 也就跟着变了** —— 这是物理限制，任何软件都做不到"对端关机了还能保持同一个 IP"。
- 你唯一的应对是：如果业务对 IP 极敏感，就在 IP 变了之后手动更新一次白名单/登录环境。

系统做了两件事降低变动概率，但**不是保证**：

1. 重连时优先连回**上次用的那个节点**（`pinned`），只要它还活着，IP 就不变
2. 自动优选只换"明显更慢"的节点（默认要求慢 2.5 倍且超过 150ms），不会为了微小差距主动换 IP

### 想要 IP 更稳，只有三条路

| 做法 | 效果 |
|---|---|
| 关掉自动优选（面板 → 参数设置） | 节点还活着就不换，只在掉线时换 |
| 多开一个粘性口（`TUNNELS=4`） | 有了备用口，主口 IP 变了可以切过去 |
| 换可控的出口（自己的家宽 + WireGuard） | 唯一能真正保证 IP 固定的做法 |

### 其他

- **Web 面板（5000，需登录）**：会话登录 + 链接一键复制 + 参数在线修改 + 维护按钮 + 运行态诊断
- **多隧道守护**：某条隧道失效只重连那一条，其余继续服务

### 面板里能做什么

打开 `http://VPS_IP:5000`，输入账号密码进（默认密码见 `/opt/gate_proxy/vpngate_info.txt`）。

| Tab | 内容 |
|---|---|
| **接入链接** | 全部 SOCKS5/HTTP/SS/SS2022/ssu 链接，**IP 和端口默认打码**，点「👁 显示」才出现，**点一下直接复制**（不再弹确认框） |
| **节点列表** | 国旗 + 主机名 + 运营商 + 并发人数 + 带宽 + 实测 RTT + 累计流量 + 智能评分；点「详情」看完整字段；一键连接 |
| **参数设置** | 国家顺位、巡检间隔、并发上限、候选数、UDP/TCP 优先、mssfix、ping-restart、轮询间隔、自动优选、通知 —— 改完即存 |
| **诊断** | openvpn 版本、隧道路由规则、gost 状态、节点池等运行态 JSON |

**主题**：右上角「🌗 主题」在暗色/亮色之间切换，默认跟随系统（`prefers-color-scheme`），选择记在浏览器本地。

**国旗**：节点列表和隧道卡片带 🇯🇵🇰🇷🇺🇸 这样的国旗。
Windows 的 Chrome 不渲染国旗 emoji（系统没有国旗字体），会显示成 `JP` `KR` 这样的两字母，
不影响识别，macOS / iOS / Android / Linux 正常显示。

**隧道卡片**：每条隧道显示当前的节点、出口 IP、真实 RTT 和**专属入口端口**，卡片上直接带「复制入口」按钮。

**隐私模式**：右上角「🔒 隐私模式」默认开启，会把 IP、端口、密码全部打码（隧道卡片里的节点/出口 IP 也一起打码），
适合截图分享或录屏。点一下切到「🔓 已显示真实」，状态记在浏览器本地。

**端口自检横幅**：页面顶部会实时显示本机实际在监听哪些端口。三种状态：

- 🟢 端口都在监听 —— 说明客户端连不上是**云安全组**的问题
- 🟡 本机没监听某些端口 —— 列出具体端口号，说明 gost 没起来
- 🔴 gost 未运行 —— 直接给排查命令

这一条就是用来区分「连接被拒绝」到底是**没进程在听**还是**云防火墙挡了**。

**维护按钮（`vg` 之外）**：全部重连 / 刷新节点库 / 清空失败黑名单 / 重启 gost / 断开全部隧道。
**改密码**：右上角「改密码」，改完立即生效并把所有已登录会话踢下线。

#### 会话与安全

- 用 Cookie 会话（`HttpOnly; SameSite=Lax`，12 小时有效），不再是浏览器原生 Basic 弹窗
- 连续输错 **6 次锁定 2 分钟**（按来源 IP）
- 也兼容 Basic 认证，方便 `curl -u user:pass` 写脚本
- 凭据存在 `/opt/gate_proxy/vpngate_credentials.json`（600），重装时会同步更新，不会出现"信息清单里的密码登不上"

#### 哪些参数能在线改，哪些要重装

| 立即生效 | 下次重连生效 | 必须重装 |
|---|---|---|
| 国家顺位、巡检间隔、并发上限、候选数、UDP/TCP 优先、设备轮询/出网探测间隔 | mssfix、ping-restart | 隧道条数、粘性端口、接入端口、路由表号 |

> 面板跑在 HTTP 上，密码在网络里是明文（Basic 认证部分）。如果面板要暴露到公网，建议在云安全组里限制来源 IP，或者前面挂一层 Nginx + 证书做 HTTPS。

出口结构：

```
客户端 ──SOCKS5/SS/HTTP──> gost (VPS)
                            ├─ tun0 ──OVPN──> 日本节点 A（并发 0 人）
                            ├─ tun1 ──OVPN──> 日本节点 B（并发 1 人）
                            └─ tun2 ──OVPN──> 日本节点 C（并发 4 人）
                          聚合口按连接轮询 + 失败自动降级
                          粘性口固定绑定其中一条
```

## 四、系统要求

- **系统**：Ubuntu 18.04/20.04/22.04/24.04，Debian 10/11/12
- **架构**：`x86_64` / `aarch64`
- **虚拟化**：**必须 KVM / 裸机**。LXC / OpenVZ 无 `tun` 与 `ip rule` 权限，安装脚本会直接检测退出
- **端口**：云安全组放行 TCP `5000` `10808` `10809` `10810` `10818..10820`，以及 UDP `10811`
- **依赖**：`openvpn`、`python3 ≥ 3.7`、`curl`、`iproute2`、`iptables`。gost 用静态二进制，不需要 Docker

## 五、安装与卸载

### 安装

```bash
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/install.sh | bash
```

装完终端会打印面板地址、账号密码和全部接入链接，也可以随时查看：

```bash
cat /opt/gate_proxy/vpngate_info.txt
```

然后浏览器打开 `http://VPS_IP:5000` 登录。

### 更新

**重跑同一条安装命令就是更新** —— 脚本是幂等的：

```bash
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/install.sh | bash
```

重跑会拉取最新版本、清掉旧版本残留、保留节点池和缓存，并重新生成密码（密码会变，记得重新看 info 文件）。

### 卸载

```bash
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/uninstall.sh | bash
```

默认只删本项目自己的东西。两个可选参数是**装在命令上**的：

```bash
# 彻底清理：连 docker 镜像和旧版遗留的 python 包一起删
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/uninstall.sh | PURGE=1 bash

# 保留节点池数据（以后重装还能接着用历史节点）
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/uninstall.sh | KEEP_DATA=1 bash
```

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `TUNNELS` | `3` | **隧道条数（1~6）**。带宽叠加就靠它；1 核机器会自动降到 2 |
| `SESSION_CAP` | `60` | 并发人数超过此值的节点直接排除。冷门节点少时可提到 100 |
| `CANDIDATES` | `5` | 每条隧道最多试几个候选 |
| `MSSFIX` | `1300` | 跨境高丢包可降 `1240`；`FIX_MTU=0` 关闭 |
| `ENABLE_BBR` | `1` | BBR + fq + conntrack 调优 |
| `PREFER_TCP` | `0` | 机房封 UDP 出站时设 `1` |
| `FAST_POLL` | `1.0` | 隧道设备轮询间隔（秒），断线检测速度 |
| `HEALTH_POLL` | `3.0` | 出网健康探测间隔（秒） |
| `PING_RESTART` | `20` | OpenVPN 多久收不到对端回应就自我退出（秒） |
| `GOST_REBIND` | `0` | 隧道换节点后是否重启 gost。**保持 0**，重启会掐断其它隧道的连接 |
| `DEFAULT_P1/P2/P3` | `JP`/`KR`/`NONE` | 国家优先级，默认不跨洲 |
| `STICKY` | `1` | 是否为每条隧道开一个粘性端口（出口 IP 不跳动） |
| `STICKY_BASE` | `10818` | 粘性端口起始号，第 i 条隧道用 `10818+i` |
| `SS2022_PORT` / `SSU_PORT` | `10810` / `10811` | SS2022 / SS UDP 中继端口 |
| `PANEL_PORT` / `SOCKS5_PORT` / `SS_PORT` | `5000`/`10808`/`10809` | |
| `PANEL_USER` / `PANEL_PASS` | `admin` / 随机16位 | 面板凭据 |
| `ROUTE_TABLE` | `100` | 起始路由表号，第 i 条用 `100+i` |
| `FORCE_DOCKER` | `0` | 强制用 Docker 跑 gost |
| `GOST_MIRROR` | 空 | GitHub 被墙时的镜像前缀 |
| `PUBLIC_IP` | 自动探测 | 生成接入链接用的公网 IP，探测失败时手填 |
| `INSTALL_DIR` | `/opt/gate_proxy` | 安装目录，所有项目文件都在这里 |
| `CLEAN` | `0` | 设 `1` 时安装前做深度清理（删 docker 镜像、压缩日志、清缓存） |
| `PURGE` | `0` | 卸载时设 `1` 会一并删 docker 镜像和 v1 遗留的 python 包 |

常用组合：

```bash
# 想要更大带宽（4 核以上机器）
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/install.sh | TUNNELS=4 bash

# 冷门节点不够用时放宽
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/install.sh | SESSION_CAP=100 TUNNELS=3 bash

# 谷歌云 / 高丢包
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/install.sh | FIX_MTU=1 MSSFIX=1240 bash

# 机房封 UDP
curl -fsSL https://raw.githubusercontent.com/ekong-aura/gate_proxy/main/install.sh | PREFER_TCP=1 bash
```

## 六、不用开面板：`vg` 命令

装完之后有个 `vg` 命令，日常看状态根本不用开浏览器：

```bash
vg            # 一眼看完：几条隧道在线、出口 IP、RTT、优选和通知状态
vg ip         # 每条隧道各自的出口 IP
vg ports      # 本机实际在监听哪些端口
vg log        # 最近 40 行 OpenVPN 日志（vg log 200 看更多）
vg gost       # gost 服务状态
vg restart    # 重启面板 + gost
```

`vg` 输出长这样：

```
◐  2/3 隧道在线   节点池 99（冷门 41）   更新于 15s 前
  up    tun0       JP       出口 219.100.37.125  RTT 18.4ms  已连 1.0h
  up    tun1       JP       出口 58.3.234.9      RTT 23.1ms  已连 2.0h
  down  tun2       已断 12s，后台恢复中
  状态: OK 3/3 条隧道健康，聚合出口正常
  上次巡检: 07:20:14   优选:开   通知:开   面板: http://66.154.118.191:5000/
```

它读的是 `/opt/gate_proxy/vpngate_status.json`（守护进程每 15 秒刷新一次），**不依赖面板进程**——
面板挂了 `vg` 照样能看。

## 七、实测带宽：每条隧道到底能跑多快

面板和 `vg` 都会显示每条隧道的**实测带宽**，用来判断哪条值得多用。

### 怎么测的

```
curl --interface tun0 --max-time 18 -o /dev/null \
     -w "%{size_download} %{speed_download} %{http_code}" \
     "https://speed.cloudflare.com/__down?bytes=3000000"
```

`--interface tun0` 把这条连接**强制绑到指定隧道**，从 Cloudflare 边缘节点下固定大小的数据，
读 curl 报出来的实际速率。测的是「VPS → 家宽节点 → CDN」这条**完整链路**，
正好等于这条隧道真实能跑多快。

几个刻意的设计：

| 设计 | 原因 |
|---|---|
| **串行测**（一条测完再测下一条） | 并行会互相抢 VPS 上行口，两个数字都是错的 |
| 至少下到 30% 或 800KB 才算有效 | 太少的样本噪声大 |
| 两条 URL（https + http） | 个别节点对 TLS 大流量异常时还有退路 |
| 结果存 `speed_mbps`，不用来算分 | 测速有成本，不适合放进选节点的评分循环 |

### 流量成本（重要）

测速**会真的消耗流量**——消耗的既是你 VPS 的出网，也是那台志愿者家宽的流量。
默认值刻意设得保守：

| 参数 | 默认 | 说明 |
|---|---|---|
| `SPEEDTEST` | 开 | 总开关 |
| `SPEEDTEST_MB` | `3` | 每次下载 3MB |
| `SPEEDTEST_INTERVAL` | `43200` | 12 小时测一次 |

按 2 条隧道算：`2 × 3MB × 2 次/天 ≈ 12MB/天 ≈ 360MB/月`（面板里会实时算出这个数）。

**如果你在谷歌云免费机（1GB/月出网额度），把它关掉**，改用面板上的「立即测速一次」手动跑。
甲骨文免费额度 10TB/月，可以放心开着，甚至把间隔调到 3600（每小时）。

### 数据怎么用

- **看哪条更值**：面板隧道卡片上的「实测带宽」，或者 `vg` 输出的带宽列
- **选固定的出口**：哪条快就用哪条的**专属端口**（`10818` / `10819`）
- 后面如果要按带宽加权轮询，这个数据就是依据 —— 目前聚合口还是均匀轮询，没有加权

### 国家顺位不再写死

第一顺位默认是 **`自动`**，不是写死的 `JP`：

- **自动**：不限国家，按评分挑（含下面说的"地理优先"加分）
- 也可以手动指定具体国家

面板 → 参数设置 → 「测一下各国实际延迟」会从**你这台 VPS** 实测每个国家节点的最低 RTT，
列表直接告诉你哪个国家最快。**不要按地图距离猜** —— 跨国线路质量差异很大，
洛杉矶到加拿大和到新加坡可能完全反过来。

### 地理优先

系统会探测 **VPS 自己所在的国家**（`ipinfo.io` → 国家码），给**同一个国家**的节点 **+8 分**（满分 100）。

为什么只加 8 分：并发人数占 50 分权重，8 分只是"轻微倾向"，不会为了同国去挤一个 80 人同时在用的节点。
VPS 在美国就优先美国节点，VPS 在日本就优先日本节点 —— 不用你手动改。

### 节点池：为什么美国节点会越来越多

VPN Gate 的公开 API **每次只返回约 99 个节点**（实测：4 种 URL 变体 + 连续拉取 3 次，结果完全一致）。
当前分布大概是：

```
JP 45   KR 26   RU 9   TH 4   HR 4   US 3   ID 2   IN/AE/RO/EG/NZ/PE 各 1
```

**但这 99 个是"此刻在线"的快照，每天都在变。** 志愿者电脑上下线，IP 会换。

所以本版加了**历史节点池**（`/opt/gate_proxy/vpngate_pool.json`）：

| 做法 | 效果 |
|---|---|
| 每次刷新把新快照**合并**进池子，不覆盖 | 池子随时间增长，一周后 200+，一个月 300+ |
| 池里的 `.ovpn` 配置一起存下来 | 历史节点随时能重连 |
| 超过 `POOL_TTL_DAYS`（默认 14 天）没再出现的淘汰 | 不会无限膨胀 |
| 历史节点评分 **−15 分**，只在在线节点不够时才启用 | 正常情况不牺牲质量 |

这就是别的项目说的"节点越用越多"的原理 —— 不是有什么特殊接口，就是**累积历史快照**。

刚装完时池子等于在线数量（99），**要跑几天才会看出增长**。面板「节点池」卡片和 `vg` 都能看到：

```
节点池 在线99 / 累积143（US 9）
```

> 美国节点从 3 个涨到 9 个，就是这么来的。不过要注意：历史节点可能已经下线，
> 系统会先试在线节点，实在不够才用历史的，失败了会进黑名单。

## 八、自动优选：节点会不会被优化

**会，而且是三层筛选：**

1. **选节点时**：按「当前并发人数 + 历史带宽 + 累计用户 + 实测 RTT」打分，不是随机挑。默认还会排除并发 >60 人的拥挤节点。
2. **掉线重连时**：优先连回**上次那个节点**（保持 IP 稳定）；它真死了才重新从池子里挑最好的。
3. **长期运行中**：每小时评估一次，如果当前节点明显比池子里的好节点慢，就主动换掉。

第 3 条就是"自动优选"，判定条件保守，避免无意义地换 IP：

| 参数 | 默认 | 含义 |
|---|---|---|
| `AUTO_OPTIMIZE` | 开 | 总开关 |
| `OPTIMIZE_RATIO` | `2.5` | 当前延迟是最好候选的 2.5 倍以上才换 |
| `OPTIMIZE_FLOOR` | `150` | 且至少慢到 150ms，20ms→45ms 这种不换 |
| `OPTIMIZE_INTERVAL` | `3600` | 每小时评估一次 |
| `SPEEDTEST*` | 见第七节 | 实测带宽（会消耗流量，默认 12 小时一次 3MB） |
| `DEFAULT_P1` | `AUTO` | 第一顺位国家，`AUTO` = 不限国家自动择优 |
| `GEO_PREFER` | `1` | 同国节点 +8 分 |
| `POOL_EXTRA` | `1` | 在线节点不够时启用历史节点池 |
| `POOL_TTL_DAYS` | `14` | 历史节点保留天数 |

一轮最多换一条隧道，避免整体抖动。换的时候会推一条通知（如果你配了 webhook）。

## 九、出问题才通知你

如果不想天天盯面板，配一个 Webhook，**平时完全静默**，只有两种情况会推：

- 所有隧道连续 3 轮（约 90 秒）都恢复失败
- 从故障中恢复

推送频率有下限（默认同类消息 30 分钟内只发一次），不会刷屏。

配置方式（面板 → 参数设置 → 出问题通知），支持两种格式：

| 格式 | 用途 |
|---|---|
| 通用 JSON | `POST {"title":"VPN Gate","text":"..."}`，飞书/钉钉/Slack 的机器人大多能用 |
| Telegram | `POST {"chat_id":"...","text":"..."}`，填 Bot Token 到 URL、填 chat_id |

点「发一条测试通知」可以立刻验证通不通。

## 十一、断线切换：能无感到什么程度

节点是陌生人家的电脑，随时可能关机。v3 的切换策略是**多隧道 + 事件驱动 + 不重启 gost**。

### 三档检测速度

| 信号 | 手段 | 发现耗时 |
|---|---|---|
| openvpn 进程退出 / 正常断开 | 轮询 `ip link show tunN`，设备立刻消失 | **≤1 秒** |
| 对端整机断电（UDP 无回应） | `curl --interface tunN` 探测 204，连续 2 次失败才判死 | **约 7~10 秒** |
| 兜底 | OpenVPN 自身 `ping 3` + `ping-restart 20` | 20 秒 |

判死后 `_wake.set()` 立刻唤醒守护线程，**不再等 30 秒巡检**。

### 关键设计：不重启 gost

`gost -L "socks5://...?interface=tun0,tun1,tun2"` 是按**设备名**做 `SO_BINDTODEVICE`，每次新建连接时内核才读设备当前 IP。所以某条隧道换了节点，**gost 不需要重启**。

反过来，一旦重启 gost，**另外两条健康隧道上正在跑的连接会被一起杀掉** —— 这就是"只坏一条却全断"的元凶（v1 的 `docker restart vpngate-proxy` 和 v2 的 `systemctl restart` 都是这个毛病）。现在默认 `GOST_REBIND=0`，`up.sh` 和面板都不再重启它。

### 实际体感

| 场景 | 发生什么 |
|---|---|
| 刷 Twitter / 逛网页 | 旧的 1/3 请求报错，浏览器立刻重试 → 新请求走健康隧道，**基本无感** |
| 看视频（HLS/DASH 分段） | 丢一个分片，播放器自动重试续上，缓冲足够时**看不出卡顿** |
| 大文件下载 / BT 单流 | 该连接会断，需要重新开始（物理上无解，对端电脑已关机） |

### 做不到的事

**在途 TCP 连接无法跨隧道迁移。** 那条连接的对端是已经关机的家宽节点，任何软件都救不回来。真要零丢包得多路径复制（MPTCP），VPN Gate 的 OpenVPN 隧道做不了。

所以目标是：**把"整段断流"降级成"1/3 连接各丢一次、1 秒内重试成功"**。这个做得到。

### 面板模式说明（重要）

`mode` 现在只有两种，**自动修复始终开启**，不会因为点了"连接"就变成不修复：

- 🟢 **自动**：断线自动修，优先国家都不可用时临时放宽到全部国家
- 🔒 **锁定国家池**：断线照样自动修，但只在你设的 JP/KR 里找，不跨洲

## 十二、性能预期与边界

**可以做到：**
- 3 隧道聚合后，HLS/DASH 类流媒体（多连接分段下载）实测可接近单节点的 2~3 倍
- 单条隧道掉线不影响业务，新连接 1~3 秒内恢复；检测 + 重连在 10 秒内完成
- 交互延迟 = `客户端→VPS` + `VPS→节点`（同国 15~40ms）
- 节点排序用**实测 RTT**（TCP 量握手 / UDP 量 ICMP），不再依赖 vpngate 那个与你的路径无关的 `Ping` 字段

**做不到（物理限制）：**
- **单条 TCP 流不会聚合**。一个 4K 视频如果只用 1 条 TCP，就只有 1 条隧道的带宽。YouTube/Netflix 走分段多连接，能吃到聚合；BT/单线程下载吃不到。
- **跨洲必然慢**。日本 VPS 到美国家宽 RTT 100~150ms，跨境丢包下单个 TCP 流吞吐会塌到几百 Kbps。所以默认 `p3=NONE`，不跨洲。
- **在途连接无法迁移**。节点关机那一刻正在跑的那条 TCP 一定断，只能靠客户端重试。
- **VPN Gate 节点是志愿者的电脑**。流量经过陌生网卡，HTTPS 内容看不到，但目标域名/时间/流量可见。别用于支付、主账号登录这类操作。

**如果想再往上走**（等预算允许）：自建或租用一条目标国家家宽 + WireGuard 反向隧道，延迟和带宽都能质变，面板与路由逻辑可直接复用。

## 十三、故障速查

| 症状 | 先看 |
|---|---|
| 代理连不上、报「连接被拒绝 / Connection refused」 | ① 面板顶部横幅：本机是否在监听那个端口 ② 云安全组是否放行了**那个具体端口**（粘性口 10818~10820 要单独放行） ③ `ss -lntp \| grep 1080` |
| 面板打不开 | 云防火墙放行了 5000 吗？`ss -lntp \| grep 5000` |
| 面板 0 节点 | 跑体检脚本看「节点库质量」，或点面板上的「更新官方节点库」 |
| 链接里的 IP 是 `10.x` / `192.168.x` | 是内网地址，客户端当然连不上。新版会自动拒绝私有 IP 并重新探测；仍失败就把 `PUBLIC_IP=公网IP` 写进 systemd 单元 |
| 只有 1 条隧道起来 | 正常，守护线程会逐条补齐；看状态文案 |
| tun 在但打不开网页 | MTU。`MSSFIX=1240` 重装，或 `ip link set tun0 mtu 1300` 试 |
| 全部显示 ⚪ 未知 | 机房封 ICMP，属正常，直接点连接 |
| 速度上不去 | 面板按「并发人数」排序，手动挑 0~5 人的节点 |
| 落地 IP 还是机房 IP | `ip rule show`、`ip route show table 100` |
| `TUNSETIFF busy` | v1 的竞态 bug，v2 起已用轮询等待修复 |
